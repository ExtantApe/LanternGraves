LanternGraves now tells Rewild where its graves are, so Rewild never resets a chunk with a grave in it.

Without this, Rewild 0.2 refuses to reset anything at all while LanternGraves runs, because it can't tell where the graves are. Servers running both need 0.1.2 for Rewild to do anything.

## Changes

- When Rewild is installed, LanternGraves reports every chunk that holds a grave. `/rewild why` names it as "a grave (LanternGraves)". Neither plugin needs the other: Rewild's interface is reached by name.
- Fails closed: while any grave file couldn't be read, its place is unknown, so LanternGraves refuses to answer and Rewild resets nothing in that world until the file is fixed and the server restarts.
- New setting `rewild.keep-graves` (default `true`). Turned off, LanternGraves doesn't report, and Rewild resets nothing while both run. Read at startup.

## Tested

- 4 new unit tests: each grave chunk reported once with its reason, chunk maths for negative coordinates, nothing reported with no graves, and the refusal while a grave file is damaged.
- New bot test `test/rewild.mjs` with Rewild 0.2.1 on a throwaway Paper 26.1.2 server, 8/8: a real grave's chunk is kept and named, a far chunk isn't, and with the setting off Rewild resets nothing and says why. Not run on 26.2 or 26.3 for this release; the other suites weren't rerun, since nothing they cover changed.

Upgrading is a jar swap. `config.yml` gains the `rewild` section on first start; grave files are unchanged.
